# Implementation notes (BUILD, initial version)

Baseline: `DESIGN-internship-registration-explorer-v0.7.md`. BUILD was authorized by the project owner on 2026-10-21 to deliver a working site without first resolving every operational decision in the design. This authorization does not approve the launch decisions listed below.

## Build decisions

Reasonable, reversible choices made where the design left a decision open.

| Decision | Choice | Reason | Design reference |
|---|---|---|---|
| Technology stack | Plain HTML and CSS generated by a small Node script; no runtime dependencies and no client JavaScript | Simplest option that meets the design: works without JavaScript, minimal page weight, nothing to keep patched. Dev-only test tools: Playwright 1.56.1 and axe-core 4.10.3 | Option C in §7.1; DEC-008 stays formally open |
| Content storage | One file, `content/site.json`, validated at build time | Simpler for organizers than per-role Markdown files | §7.4 content model; §7.6 folder layout simplified |
| Form link validation | Build requires the exact `…/forms/d/e/{approvedFormId}/viewform` URL; no prefill parameters | Prevents a wrong or substituted form | DP-11, DAC-14; prefill (OD-09) not implemented |
| Register button placements | Hero, header (≥ 768 px), each role, How to apply, 404 page | Requested "prominent" Register links | DP-15, still subject to DEC-002 |
| Mobile sticky Register bar | Not built | Unapproved proposal that needs usability evidence first; would also need JavaScript | DP-03, DEC-009 |
| Role filters | Not built | Only proposed above 8 roles; the build warns if more than 8 are published | DP-05 |
| Security headers | `<meta>` CSP (`default-src 'self'`, no inline styles or scripts, `form-action 'none'`) and referrer policy in each page | Works on any host. `frame-ancestors` and HSTS need real response headers once the host and header policy are decided | DP-14, DEC-013, DEC-006 |
| Brand | Provisional neutral palette and system fonts from D-05; organization name as text, no logo | No approved branding | DP-07, OD-05 |
| Analytics | None | Not approved | OD-08 |

## Verified in this environment

- `npm test`: 16 unit tests pass. They cover content validation (exact form URL, statuses, dates, release mode), every Register link's URL and same-tab behaviour, closed and upcoming states with no form links, unique accessible names, the zero-role and one-role layouts, HTML escaping, no forms, inputs or inline code, and the build output.
- `npm run test:e2e`: 14 browser tests pass in Chromium 141 at 360×640, 320×568 and 1280×800. They cover the hero and role Register links reaching the exact form URL in the same tab, Back returning, no console errors, no horizontal scroll, the key content in the first mobile viewport, keyboard use of role details and the skip link, header navigation, JavaScript disabled, HTTP 404, and axe-core with no serious or critical WCAG 2.2 A/AA violations on the home and 404 pages.
- `npm run build` succeeds and lists the 26 placeholders; `npm run build:release` exits with code 1 while placeholders remain.

## Deferred: timestamp accuracy and the deadline tolerance

**Status: deferred and unresolved.** The design (v0.7 §7.10, DAC-37) describes how a hard registration cutoff could be enforced at review time using Google Forms' recorded timestamps, including a proposed 10-second allowance for submission delay. The latest independent review of v0.7 found that this timestamp-accuracy approach still has an unresolved issue.

The project owner deferred it so it doesn't block the website. Nothing in this build addresses it: there is no timestamp verification, no automatic deadline enforcement and no automatic form closure.

What this means in practice: the website itself is unaffected. It only matters if the program chooses a hard cutoff that relies on response timestamps. Until the issue is resolved, closing registration stays a manual step, and that step is what DEC-010 must decide: switch the form off, then set `status` to `"closed"`.
